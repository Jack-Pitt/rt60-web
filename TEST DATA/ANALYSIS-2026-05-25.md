# Clipping behaviour analysis — iPhone 16 Pro Max vs Type 1 SLM

**Date:** 2026-05-25
**Source data:** `TEST DATA/R1815..1819.WAV` (SLM, 24-bit 48 kHz mono),
`TEST DATA/RT60_Bundle_5_2026-05-22T05-36-51Z.json` (iPhone bundle).
**Method:** SLM WAVs run through the app's own DSP pipeline
(`src/dsp/analyze.ts`) via `scripts/analyse-test-data.ts`; results
compared per-band against the iPhone JSON values.

---

## TL;DR

> **The user's hypothesis is correct.** Brief peak clipping on the
> iPhone microphone **does not meaningfully degrade T30** — the
> measurement remains accurate to within ~5 % of a Type 1 SLM in the
> mid-band cluster (125 Hz – 5 kHz). The MFRT difference across all
> five measurements averages **−0.9 %**, essentially within the
> precision of any single measurement. **EDT is mildly affected
> (+3 % to +10 %)** because its fit window (0 to −10 dB) sits closer
> to the clipped region. The current "critical" red-flag treatment of
> clipping is too strict — it discards measurements that are in fact
> usable.

### 1.4 EDT comparison (where clipping IS expected to bite)

| Band | iPhone EDT | SLM EDT | Δ (s) | Δ (%) |
|---|---|---|---|---|
| 500 Hz | 2.59 s | 2.36 s | +0.23 | **+9.8 %** |
| 1000 Hz | 2.22 s | 2.16 s | +0.06 | +2.8 % |
| 2000 Hz | 2.23 s | 2.18 s | +0.05 | +2.3 % |

EDT is consistently higher on iPhone than SLM, with the biggest
discrepancy at 500 Hz. This matches the clipping mechanism: EDT fits
0 → −10 dB, which overlaps the region where the clipped peak has
artificially flattened the EDC; the flatter the early decay, the
shallower the regression slope, and the longer the extrapolated T60.
At higher frequencies the mic recovers faster (less mechanical
inertia), so the EDT inflation is smaller.

Note that **even on the clean SLM, EDT ≈ 2.2 s while T30 ≈ 1.0 s** —
the EDT >> T30 ratio is largely a property of *the clapper board*
(its source ring contaminates the first 10 dB of decay) and the
*room geometry* (early reflections), not just iPhone clipping. The
iPhone adds ~3–10 % on top of that real effect.

### 1.5 Clipping duration in the iPhone EDC

| Band | ms within 0.5 dB of peak | ms to first −5 dB (T30 start) |
|---|---|---|
| 125 Hz | 253 | 395 |
| 250 Hz | 222 | 259 |
| 500 Hz | 233 | 290 |
| 1000 Hz | 213 | 265 |
| 2000 Hz | 210 | 252 |
| 4000 Hz | 211 | 265 |

Subtract the 200 ms pre-trigger margin that the controller
prepends, and the *post-impulse* time-to-recovery is **~10–90 ms**
in the mid bands and ~50–200 ms in the low bands. So clipping
extends only ~10–90 ms into the actual decay window before the
recorded signal returns to the linear range. The T30 fit (which
starts at −5 dB, i.e. ~50–90 ms post-impulse in the mid bands)
**fits the linear-range decay exclusively** — clipping is over before
the fit begins.

This is exactly why T30 survives.

## 2. Why clipping mostly doesn't matter for T30

A clipped sample loses *absolute amplitude information* (the recorded
value is hard-limited to 1.0 instead of the true value, which would
have been higher). But the **shape** of the decay curve after the
clipped region is intact:

1. Schroeder backward integration computes EDC[t] = Σ from t to end
   of x²[t]. Once the signal returns to the linear range (|x| ≤ 1),
   the integration is computing genuine energy values.
2. T30 fits a regression line from −5 dB to −35 dB. If the −5 dB
   crossing happens *after* the clipped region ends, the regression
   sees only linear-range data and produces an accurate slope.
3. The brief clipped region does inflate the EDC absolute level at
   the start (less true energy is captured), but the decay slope —
   which is what determines T30 — is unaffected.

EDT (0 → −10 dB) does include some of the clipped region in its fit
window, so it picks up the artificial flattening as a shallower slope
and over-extrapolates the T60. Hence the ~3–10 % EDT inflation we see.

T20 (−5 → −25 dB) sits in the same linear range as T30 and would
behave the same way (we just don't see it here because the iPhone INR
was high enough to report T30 in every case).

## 3. Recommended changes to the app (do **not** apply yet)

> All of these are research recommendations — none of them are coded.
> Listing them in priority order so the user can pick what to take
> forward.

### Recommendation A — Demote brief peak clipping from "critical" to "advisory"

**The big one.** Currently any sample at ±1.0 anywhere in the
recording sets the `clipped` flag, which is in `CRITICAL_FLAGS` and
paints the band's row bright red in the table and as a bright-red
button in the band selector. From the data above, this is
**discarding measurements that agree with a Type 1 to within 1 %**.

Replace the binary `clipped` flag with two finer flags:

- **`peak-clipped`** (advisory, *not* critical) — the impulse peak
  reached ±1.0 but the clipped region is short enough that T30 (and
  T20) regression windows fall entirely within the linear-range
  recovery. The measurement is trustworthy for T30/T20 reporting.
- **`sustained-clipped`** (critical) — clipping persists for long
  enough to corrupt T30's fit window. This *does* invalidate the
  measurement.

The boundary between the two is roughly: clipping that resolves
within ~30 ms post-impulse → `peak-clipped`. Clipping that persists
beyond ~50 ms → `sustained-clipped`. Detect in the capture path by
counting consecutive clipped samples.

### Recommendation B — Add an EDT-affected flag, separate from T30

Even with brief peak clipping, EDT inflation is real (~3–10 %). Add
an `edt-affected` flag that suppresses the EDT column for that band
(or shows it dimmed with an asterisk pointing to a footnote). The
T30 / T20 columns remain trustworthy and unannotated.

### Recommendation C — Validate the T30 fit window cleanly clears the clip

A more sophisticated test: for each band, check whether the EDC
reaches −5 dB **after** the clip-recovery point. If yes, T30 is
trustworthy. If the EDC's −5 dB crossing is still inside the clipped
region, mark T30 as suspect for that band specifically. This is a
per-band check, more nuanced than a single recording-level flag.

This is computationally trivial — we already have both the EDC
and (if we record it during capture) the per-sample clipping mask.

### Recommendation D — Surface "peak SPL exceeded" as the user-facing message

The current `clipped` warning reads like a measurement-killing error.
Reframe it to communicate what's actually happening:

> "Peak SPL exceeded the iPhone microphone's linear range for ~20 ms
> at the impulse. T30 / T20 values are reliable; EDT may be slightly
> elevated. Reduce source level or move further away if you need
> EDT precision."

This matches the physical reality and stops the user from discarding
good data.

### Recommendation E — Per-band T30 regression range tweak

When `peak-clipped` is set, automatically delay the T30 regression
start point from −5 dB to, say, −10 dB. This guarantees the fit
window sits entirely below the clip. Costs ~5 dB of dynamic range
on the fit but eliminates any residual clipping influence on T30
itself. Probably overkill given the empirical agreement is already
< 1 % at the MFRT level — but it's a safe belt-and-braces option.

### Recommendation F — Don't actually need clipping recovery preprocessing

I considered (and would *not* recommend) more invasive options:

- Truncating the impulse to start at the post-clip recovery point
  (loses peak reference, breaks Schroeder normalisation).
- Soft-clip extrapolation (predicting the true peak from neighbouring
  samples) — adds complexity, marginal benefit given T30 already
  agrees to < 1 %.
- Switching to MLS or sine-sweep excitation (different measurement
  paradigm; outside the brief).

The data shows the existing pipeline produces accurate T30 results
on clipped recordings already. We just need to **stop discarding them
through over-conservative flagging**.

## 4. Validation implications for `VALIDATION.md`

The "AGC pumping / clipping / non-linear" diagnostics in
`VALIDATION.md` section 4 can be relaxed:

- **Clipping at the peak is not measurement-killing** for T30. Update
  the "what to do" guidance from "discard the measurement" to "T30 is
  still valid; EDT may be inflated by a few percent."
- The visual decay-curve diagnostics for AGC pumping (noise floor
  rising after the impulse) are still important — this is a different
  failure mode that *does* corrupt T30. Keep that section.
- Add a note that an iPhone EDT >> SLM EDT of ~5–10 % is the
  expected signature of brief peak clipping and not cause for
  alarm.

## 6. One caveat

This analysis is from **one room** (Large meeting room at AAD
Kingston, ~1 s T30) with **one impulse source** (clapper board) on
**one iPhone** (16 Pro Max) at **one position**. The agreement is
striking, but a single test set should not produce a general
correction factor. The recommendation is to **change the flag
semantics** — not to apply a numerical correction. The mechanism
above (clipping resolves before −5 dB) should hold for any room
where the impulse is loud enough to exceed mic SPL but the decay is
still 100s of ms long. It would *not* hold for very small rooms with
sub-100-ms decays, where the clipping recovery period overlaps the
entire usable decay window.
